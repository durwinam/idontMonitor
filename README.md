## معرفی

**idontMonitor** ابزاری برای پایش و مدیریت سرورهای لینوکسی و VPS است که برنامه، رابط وب، تنظیمات، ترجمه‌ها و ابزارهای مدیریتی را در یک ساختار منظم ارائه می‌کند.

هدف پروژه، فراهم‌کردن دیدی روشن‌تر از وضعیت سرور، ساده‌ترکردن عملیات روزمره و ایجاد بستری قابل توسعه برای قابلیت‌های مانیتورینگ و مدیریت سرویس‌ها است.

## قابلیت‌های پروژه

- رابط وب برای مشاهده و مدیریت وضعیت سرور
- ساختار مستقل برای برنامه، رابط کاربری و فایل‌های استاتیک
- پشتیبانی از ترجمه‌های فارسی و انگلیسی
- مدیریت سرویس برنامه با `systemd`
- ابزار خط فرمان برای وضعیت، گزارش‌ها، راه‌اندازی مجدد و به‌روزرسانی
- محیط مجازی پایتون برای وابستگی‌های برنامه
- ساختار نسخه‌بندی برای نگهداری نسخه‌های نصب‌شده
- پشتیبانی از نصب و ارتقای برنامه با حفظ تنظیمات موجود، مطابق امکانات نسخه

> قابلیت‌هایی مانند پایش اختصاصی ترافیک هر تانل، حسابداری سرویس‌ها و مدیریت پیشرفتهٔ شبکه باید بر اساس پیاده‌سازی واقعی و منبع دادهٔ معتبر هر سرویس ارزیابی شوند؛ وجود نام یک قابلیت در مستندات به‌تنهایی تضمین‌کنندهٔ فعال‌بودن آن نیست.

## پیش‌نیازها

- سرور مبتنی بر Debian یا Ubuntu
- دسترسی مدیریتی `root` یا `sudo`
- اتصال اینترنت برای دریافت سورس و وابستگی‌ها
- دسترسی به مخازن بسته‌های سیستم‌عامل
- دامنهٔ معتبر و دسترسی به پورت‌های موردنیاز، در صورت استفاده از HTTPS

## نصب سریع

برای دریافت و اجرای نصب‌کننده از مخزن رسمی:

```bash
curl -fsSL https://raw.githubusercontent.com/durwinam/idontMonitor/main/install.sh -o install.sh
less install.sh
sudo bash install.sh
```

این روش به شما اجازه می‌دهد پیش از اجرای اسکریپت با دسترسی مدیریتی، محتوای آن را بررسی کنید.

نصب‌کننده با توجه به پیاده‌سازی نسخه، وابستگی‌های لازم را آماده می‌کند، محیط مجازی پایتون می‌سازد، فایل‌های برنامه را نصب می‌کند و سرویس `idontmonitor` را پیکربندی می‌کند.

**توصیهٔ امنیتی:** قبل از نصب یا ارتقا، از تنظیمات و داده‌های مهم پشتیبان بگیرید و نصب‌کننده را بررسی کنید.

## مدیریت با خط فرمان

پس از نصب، ابزار `idontMonitor` برای عملیات مدیریتی در دسترس است.

### وضعیت سرویس

```bash
sudo idontMonitor status
```

### مشاهدهٔ نسخه

```bash
idontMonitor version
```

### مشاهدهٔ گزارش‌ها

```bash
sudo idontMonitor logs
```

برای خروج از گزارش زنده، `Ctrl+C` را فشار دهید.

### راه‌اندازی مجدد، اجرا و توقف

```bash
sudo idontMonitor restart
sudo idontMonitor start
sudo idontMonitor stop
```

### راهنما

```bash
idontMonitor help
```

> فرمان‌های بالا باید با دستورات واقعاً پیاده‌سازی‌شده در فایل CLI نسخهٔ منتشرشده هماهنگ باشند. اگر فرمانی در نسخهٔ نصب‌شده وجود ندارد، ابتدا باید پیاده‌سازی شود؛ README نباید قابلیت اجرا‌نشده را وعده دهد.

## به‌روزرسانی

برای اجرای سازوکار به‌روزرسانی نسخهٔ نصب‌شده:

```bash
sudo idontMonitor update
```

پیش از ارتقا، وضعیت فعلی سرویس و فضای دیسک را بررسی کنید:

```bash
sudo idontMonitor status
df -h /
```

پس از ارتقا، سلامت سرویس را بررسی کنید:

```bash
sudo systemctl status idontmonitor --no-pager
sudo journalctl -u idontmonitor -n 100 --no-pager
```

نسخه‌های برنامه، تنظیمات و داده‌های پایدار باید مطابق ساختار نصب‌کننده از یکدیگر جدا نگهداری شوند. رفتار پشتیبان‌گیری، بازگشت به نسخهٔ قبلی و حفظ تنظیمات باید در خود کد نصب و به‌روزرسانی تضمین شود.

## مسیرهای مهم

| مسیر | کاربرد |
|---|---|
| `/opt/idontmonitor/current` | نسخهٔ فعال برنامه |
| `/opt/idontmonitor/releases` | نسخه‌های نصب‌شده |
| `/etc/idontmonitor` | تنظیمات برنامه |
| `/var/lib/idontmonitor` | داده‌های پایدار |
| `/var/log/idontmonitor` | مسیر اختصاصی گزارش‌ها |
| `/usr/local/bin/idontMonitor` | ابزار خط فرمان |
| `/etc/systemd/system/idontmonitor.service` | فایل سرویس `systemd` |

## عیب‌یابی

اگر پنل باز نمی‌شود یا سرویس اجرا نشده است، ابتدا وضعیت سرویس را بررسی کنید:

```bash
sudo systemctl status idontmonitor --no-pager -l
```

سپس گزارش‌های اخیر را بخوانید:

```bash
sudo journalctl -u idontmonitor -n 100 --no-pager
```

برای مشاهدهٔ گزارش زنده:

```bash
sudo journalctl -u idontmonitor -f
```

موارد زیر را نیز بررسی کنید:

- نصب‌شدن وابستگی‌های Python
- معتبر بودن فایل تنظیمات
- آزاد بودن پورت برنامه
- مجوزهای دسترسی فایل‌ها و پوشه‌ها
- وضعیت reverse proxy و گواهی TLS، در صورت استفاده از HTTPS
- دسترسی شبکه به سرور

## آزمون‌ها

برای اجرای آزمون‌های پروژه، ابتدا محیط توسعه و وابستگی‌های آن را مطابق فایل‌های پروژه آماده کنید.

در صورت استفاده از `pytest`:

```bash
python3 -m pytest -q
```

یا اگر پروژه از آزمون‌های استاندارد کتابخانهٔ پایتون استفاده می‌کند:

```bash
python3 -m unittest discover -s tests -v
```

فقط فرمانی را به‌عنوان روش رسمی آزمون معرفی کنید که با ساختار واقعی مجموعهٔ تست نسخه سازگار باشد.

## امنیت

- قبل از اجرای اسکریپت نصب یا به‌روزرسانی، کد آن را بررسی کنید.
- رمزها، توکن‌ها و اطلاعات حساس را در مخزن عمومی قرار ندهید.
- دسترسی فایل‌های تنظیمات و نسخه‌های پشتیبان را محدود نگه دارید.
- پس از هر ارتقا، وضعیت سرویس و گزارش‌های آن را بررسی کنید.
- برای گزارش آسیب‌پذیری، دستورالعمل‌های `SECURITY.md` را دنبال کنید.
