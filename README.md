## معرفی

`idontMonitor` یک پنل تحت وب برای پایش منابع سرور، وضعیت شبکه، سرویس‌ها و ابزارهای مدیریتی است. رابط وب اطلاعات را از بک‌اند محلی دریافت می‌کند و برای نصب روی سرور لینوکسی شخصی یا عملیاتی طراحی شده است.

## قابلیت‌ها

- پایش مصرف CPU، حافظه، فضای دیسک، uptime و load average
- نمایش نرخ دریافت و ارسال شبکه و تاریخچهٔ ترافیک در صورت وجود دادهٔ معتبر
- آزمون سرعت اتصال با انتقال واقعی و محدودشده
- بررسی تأخیر، نوسان تأخیر و از دست رفتن بسته‌ها در صورت قابل‌اندازه‌گیری بودن
- احراز هویت پنل، محدودسازی تلاش‌های ورود و ثبت رویدادهای ورود
- رابط واکنش‌گرا برای دسکتاپ و موبایل
- زبان فارسی و انگلیسی با پشتیبانی RTL/LTR
- مدیریت سرویس‌ها و مشاهدهٔ وضعیت سرویس‌های تانل
- کارت‌های اختصاصی تانل برای نمایش وضعیت، پروتکل شناسایی‌شده و شمارنده‌های RX/TX در صورت موجود بودن منبع معتبر
- نمایش مجموع ترافیک فقط بر پایهٔ شمارنده‌های قابل‌خواندن؛ منابع ناموجود نباید به‌صورت صفر یا عدد حدسی جا زده شوند
- رنگ‌بندی هماهنگ با تم، کنترل‌های روشن/خاموش اختصاصی و بهینه‌سازی نمایش موبایل
- لینک‌های رسمی GitHub و Telegram در رابط پنل

## مدیریت تانل و آمار ترافیک

در نسخهٔ `1.9.9`، شناسایی سرویس‌های BackPack از نام سرویس systemd و آرگومان پیکربندی آن انجام می‌شود. برای نمونه، سرویس `backpack-client-2165.service` باید به فایل پیکربندی همان نمونه، مانند `/etc/backpack/client-2165.toml`، نگاشت شود. Snapshot آمار BackPack در صورت وجود در کنار پیکربندی و با نام متناظر `client-2165.metrics.json` خوانده می‌شود.

فیلدهای `bytes_in` و `bytes_out` به‌ترتیب برای دریافت و ارسال استفاده می‌شوند و فیلد `transport` می‌تواند نام ترنسپورت ثبت‌شده، مانند `tcpmux` یا `stealth`، را فراهم کند. سرویس‌های مدیریتی مانند `backpack-monitor.service` و `backpack-webui.service` نباید به‌عنوان تانل در مجموع ترافیک محاسبه شوند.

**محدودیت مهم:** قالب فایل، محل Snapshot، نام فیلدها و دسترسی کاربر سرویس باید روی سرور مقصد تأیید شود. اگر منبع معتبر در دسترس نباشد، آمار آن نمونه ممکن است ناموجود نمایش داده شود و مجموع کل نیز باید پوشش ناقص را منعکس کند. وجود داده در یک Snapshot به‌تنهایی اثبات نمی‌کند که شمارنده در تمام نسخه‌های موتور با یک معنا یا بازهٔ زمانی تولید می‌شود. آمار روی VPS واقعی را پس از نصب و تولید ترافیک آزمایش کنید.

## مرکز به‌روزرسانی

در منوی **Update Center**، نسخهٔ نصب‌شده با انتشار پایدار GitHub مقایسه می‌شود. نصب خودکار تنها زمانی قابل اتکاست که انتشار رسمی، آرشیو نسخه‌دار و SHA-256 معتبر و هم‌خوان داشته باشد.

- آرشیو انتشار باید نام نسخه‌دار مورد انتظار پروژه را داشته باشد.
- ابزار به‌روزرسانی باید آرشیو و نسخه را پیش از نصب اعتبارسنجی کند.
- پس از ارتقا، سلامت سرویس باید بررسی شود و در صورت پشتیبانی سازوکار نصب، امکان بازگشت به نسخهٔ قبلی وجود داشته باشد.
- تنظیمات و داده‌های پایدار باید خارج از مسیر نسخهٔ برنامه نگهداری شوند.

تا زمانی که انتشار رسمی شامل ZIP و digest معتبر در GitHub موجود نباشد، قابلیت به‌روزرسانی از راه دور را به‌عنوان انتشار تأییدشده تلقی نکنید.

## پیش‌نیازها

- سیستم‌عامل لینوکس؛ نصب‌کننده برای محیط‌های Debian/Ubuntu تهیه شده است.
- Python و وابستگی‌های ثبت‌شده در `requirements.txt`.
- دسترسی مدیریتی برای نصب سرویس systemd و تنظیم وابستگی‌های سیستم.
- دسترسی شبکه برای دریافت وابستگی‌ها و اجرای آزمون سرعت.
- برای مدیریت سرویس‌ها و مشاهدهٔ برخی شمارنده‌ها، مجوزهای مناسب خواندن اطلاعات systemd و فایل‌های سرویس.

## نصب

روش پیشنهادی، دریافت مخزن رسمی و بررسی نصب‌کننده پیش از اجراست:

```bash
git clone https://github.com/durwinam/idontMonitor.git
cd idontMonitor
less install.sh
sudo bash install.sh
```

پورت، مسیر نصب، دامنه و روش HTTPS ممکن است به تنظیمات نصب‌کننده و محیط مقصد وابسته باشند. قبل از اجرا، اسکریپت را بخوانید و مقادیر پیشنهادی را با نیاز سرور تطبیق دهید.

## ساختار سورس

```text
idontMonitor/
├── app/
│   ├── main.py              # برنامه FastAPI و API اصلی
│   └── ops.py               # عملیات مدیریتی و شناسایی سرویس‌ها
├── static/
│   ├── index.html           # پنل اصلی
│   ├── login.html           # صفحه ورود
│   ├── app.js               # رفتار تعاملی رابط
│   ├── i18n.js              # زبان رابط
│   ├── style.css            # استایل و واکنش‌گرایی
│   └── ...                  # لوگوها و منابع ثابت
├── locales/
│   ├── en/messages.json     # واژه‌نامه انگلیسی
│   └── fa/messages.json     # واژه‌نامه فارسی
├── docs/                    # مستندات معماری، نصب و API افزونه
├── scripts/                 # ابزارهای عملیات و به‌روزرسانی
├── systemd/                 # فایل سرویس systemd
├── tests/                   # تست‌های واحد و سازگاری
├── install.sh               # نصب‌کننده
├── requirements.txt         # وابستگی‌های Python
├── VERSION                  # نسخه سورس
├── CHANGELOG.md             # تاریخچه تغییرات
└── README.md                # راهنمای پروژه
```

این ساختار راهنمای کلی سورس است؛ برای جزئیات دقیق هر نسخه، فایل‌ها و اسکریپت‌های همان نسخه را بررسی کنید.

## معماری و قواعد توسعه

- هر فایل باید مسئولیت مشخص و قابل توضیحی داشته باشد.
- منطق رابط کاربری، واژه‌نامه‌ها، استایل‌ها و منطق سمت سرور از یکدیگر تفکیک شوند.
- از نام‌گذاری معنادار، توابع کوتاه و تست‌پذیر و فرمت‌بندی استاندارد استفاده شود.
- اسرار، رمزها و توکن‌ها نباید در سورس یا مستندات عمومی قرار گیرند.
- تغییرات باید با تست واحد، تست یکپارچگی و تست رگرسیون همراه شوند.
- قابلیت‌های موجود، تاریخچهٔ ترافیک و تنظیمات اتصال هنگام ارتقا باید حفظ شوند.

## زبان فارسی و فونت وزیرمتن

زبان از انتخاب‌گر بالای پنل تغییر می‌کند. در حالت فارسی، جهت صفحه `RTL` و فونت Vazirmatn فعال می‌شود؛ در حالت انگلیسی، رابط به `LTR` برمی‌گردد. در صورت استفاده از منابع محلی فونت، رابط برای نمایش فارسی به سرویس فونت خارجی وابسته نخواهد بود.

## اجرای تست‌ها

در پوشهٔ ریشهٔ پروژه، فرمان‌های زیر را اجرا کنید. برخی تست‌ها ممکن است به وابستگی‌های توسعه نیاز داشته باشند:

```bash
node --check static/i18n.js
python tests/test_syntax.py
python tests/test_units.py
```

در صورت نصب بودن pytest:

```bash

```

## عیب‌یابی سرویس

نام سرویس ممکن است بسته به نسخهٔ نصب و محیط متفاوت باشد. برای سرویس systemd با نام `idontmonitor`:

```bash
sudo systemctl status idontmonitor
sudo systemctl restart idontmonitor
sudo journalctl -u idontmonitor -n 100 --no-pager
```

برای بررسی سرویس‌های BackPack و مسیر اجرای آن‌ها:

```bash
systemctl list-units --all --type=service --no-legend --no-pager |
  grep -Ei 'backpack|ctunnel|paqet|tunnel'

systemctl show backpack-client-2165.service \
  -p FragmentPath -p ExecStart -p IPAccounting \
  -p IPIngressBytes -p IPEgressBytes
```

قبل از اشتراک‌گذاری خروجی‌ها، هر رمز، توکن یا اطلاعات اتصال محرمانه را حذف کنید.

## امنیت و نگهداری

- گذرواژه، کلید نشست، فایل پیکربندی و داده‌های تاریخچه را منتشر نکنید.
- پیش از ارتقا، از پیکربندی و داده‌های پایدار نسخهٔ پشتیبان تهیه کنید.
- اسکریپت نصب و به‌روزرسانی را پیش از اجرا بررسی کنید.
- آزمون سرعت ترافیک واقعی مصرف می‌کند و نتیجه به مسیر شبکه و نقطهٔ پایانی وابسته است.
- تست محیط توسعه به‌تنهایی عملکرد روی VPS مقصد را اثبات نمی‌کند.
- برای آمار تانل، از جمع‌زدن چند منبعی که ترافیک یکسانی را می‌شمارند خودداری کنید تا دوباره‌شماری رخ ندهد.
